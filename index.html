Developer guide · GPS module

GPS Live Tracking

Everything a new engineer needs before touching the GPS screens: which API feeds which piece of UI, and how the live map actually keeps itself up to date.

⚠ Read this before anything else

There is no setInterval anywhere in the GPS module.

The live map looks like it polls every 10 seconds. It doesn't. It's a self-perpetuating callback chain — the API result triggers a 10-second marker animation, and the animation's own completion callback is what fires the next API call. Watch it happen below.

① → ④ API round-trip
Location fetched, then reverse-geocoded. Fast, variable duration.
② → ③ Marker animates
Fixed 10,000ms. This duration is the "refresh interval" you observe.
The white dot
onAnimationComplete() — when it reaches ③, that callback fires the next API call.
running · 0s elapsed · 0 cycles completed
terminal 
grep -rn "setInterval" app/views/Gps app/views/GpsTracker app/components/GPSMarker app/model/Gps.js
# → zero matches
💡

API returns a point → point is plotted & the marker is animated to it (10s) → the animation's completion callback fires → that callback calls the API again. If the animation is slow, the next request is late. If the animation is cancelled, the chain stops forever until something restarts it. Everything else in this module follows from that one fact.

§3Live tracking

The live-tracking cycle (GpsActiveMap), step by step

This is the loop introduced in §0, laid out call by call.

3.1 Bootstrap

componentDidMount (GpsActiveMap.js:146) has two arrival paths:

  • From a truck-list card → singleTruckObeject has no lastUpdate → truckInfo is called → fetchGpsAddressDone() builds lastUpdate → setData().
  • From the dashboard map → lastUpdate is already present → setData() immediately.

3.3 What can stop the loop

Cause Mechanism
Truck changed via dropdown resetValueOnDropdown() sets this.firstCallCheck = null → updateDataOnInterval returns early. Restarted by the fresh truckInfo → setData → updateLocation chain (which resets firstCallCheck = 0).
Screen unmounted componentWillUnmount calls markerRef.stopAnimatingMarkerAlongPolyline() and nulls markerRef / mapViewRef. cancelAnimationFrame means onAnimationComplete never fires.
API failure checkErrorNetOrApi opens the error / no-internet modal and does not re-arm the loop. The user must tap "try again", which pops the screen.
A new animateMarkerAlongPolyline while one is running stopAnimation() is called first, so the previous cycle's completion callback never fires — the new animation owns the chain.

3.4 Camera / recentre behaviour

  • AnimatedMarker.checkAndRecenterMap compares the interpolated position against getMapBoundaries() and re-centres only when the truck leaves the visible box and isMapRecentered === true.
  • Any user gesture (onPanDrag, onPress, onDoublePress, zoom buttons) calls showTrackButton() → sets shouldStopAnimating = true and markerRef.setMapRecenterFlag(false), so the map stops chasing the truck and the "track" chip appears.
  • Tapping the chip calls recenter() (base class) → reads the marker's real position, animates the camera to it, hides the chip, and sets setMapRecenterFlag(true).
§4Architecture

GpsBaseComponent — the base class

File: app/views/GpsBaseComponent/index.js. Extended by GpsActiveMap, GpsDashboardMap, and all four truck-list screens. It renders nothing; it's a behaviour mixin implemented as a React.PureComponent subclass.

Module-level constants: defaultLocation = [23.78812, 90.397517], LATITUDE_DELTA = 0.09512, LONGITUDE_DELTA = 0.0018625, and a module-scoped currentTruckDetail used by the expiry modals.

Member Purpose Gotcha
getFetchFlag() true only when all three of fetchGpsAddressDoneStatus, fetchTruckMillageStatus, fetchTruckEngineOffTimeStatus are true. This is the fan-in gate for the three parallel calls. If a subclass forgets to set one of the three flags (e.g. basic package skips mileage), the loading modal never closes. That's why every early-return path explicitly sets the flag to true.
resetApiStatusVariable(status) Resets all three flags to false when status === true. Called after the modal/sheet is shown so the next cycle can gate again.
checkModalAndLoadingStatus() 500ms delayed setState that opens the details modal and closes the loader when getFetchFlag() is true. Overridden in GpsDashboardMap to also clear markerPressInProgress.
fetchTruckMillage() Callback for getMileageAgainstImeiID. Reads this.TruckMileageObj (set by the model). Writes daysMileage + lastMileageCalculationTime. Branches on this.pageName: GpsDashboardMap writes to state, everyone else writes to this.truckObject and calls hideLoadingModal(). daysMileage is nulled unless positive; timestamp nulled for basic packages.
fetchTruckEngineOffTime() Callback for lastStopTime. Reads this.TruckEngineOffObj[imeiID].engine_off_time. Same pageName branch. Model stores results keyed by imei ({[imeiID]: response, ...prev}) so a stale response for another truck can't overwrite the current one.
recenter() Re-centres on the marker's current interpolated position (not the last API point), clears totalDistanceVisited, re-enables auto-recentre. Fires a Facebook analytics event unless isGpsDemo.
getMarkerPositionAndRecenter(event) animateCamera to event lat/lng (strings, parsed) or to state.region, after a 100ms delay. Also used as the onGetPosition prop of AnimatedMarker.
updateDataOnInterval(lastLocation, lastUpdate) The heart of live tracking. See §3.2. Guarded by firstCallCheck == null. Mutates this.truckObject directly — the UI only refreshes because setState({region, markerRotation}) triggers a re-render in the same tick.
checkDistanceAndAnimate(new, prev) Accumulates haversine distance and animates the camera once imaginaryCircleRadius (default 250m) is exceeded. Currently dead on GpsActiveMap — only animate() calls it, and animate() is never invoked (legacy of the old DeviceEventEmitter marker bridge).
getAddressFromLatLng(response) Builds the Bangla "Last update" string and hands off to updateDataOnInterval. Called by Geofencing.getAddressFromLatLng on success and on failure (because updateDataOnError = true), so a geocoding outage degrades to "time only" instead of freezing the loop.
dataFetchDone() Bridge from locationInfoAgainstImeiIDs → reverse geocode. Name collision warning: Geofencing model also calls ctx.dataFetchDone(responseJson) for the geofence list — different screens, same method name.

redirectToPackageRenewPage() Routes to StandardPackage with renew: true when the package type is standard. —

6.2 Native side — CustomMapView.java

CustomMapViewModule (a SimpleViewManager) exposes:

  • Props — latList, lngList, locationObject, speed, screenWidth, screenHeight, gpsDeviceName, playTimeline.
  • Commands — onTestCallback (1), onReadyView (2), onRemoveView (3).

onReadyView() clears polylines, resets the timeline range, removes the marker, clears padding and calls mapView.getMapAsync(this). onMapReady → onReady() which, in one pass over locationObject:

  1. computes a bearing per point (getAngleFromLatLng, reusing the previous angle when the point did not move) into rotationList;
  2. builds polyz (the LatLng route);
  3. builds progressSpan — contiguous engine-on / engine-off runs used to colour the seek bar (green color_green / red color_error);
  4. records the seek-bar indices matching playTimeline.start / .end (setProgressToPlayTimeline);
  5. bucket-sorts points into locationListStop, locationListOverSpeed, locationListDeviceRemoved and adds their markers after the main loop (markers are batched for performance);
  6. drawPolylineAndMarkerDefault() — grey full-route polyline, start/end markers, the truck marker, animateCameraToLatLngBounds(min, max);
  7. initDataToSeekbar().

Playback animation, animatePolylineAndMarker(progress):

CustomMapView.java 
playbackHandler = new Handler(Looper.getMainLooper());
playbackRunnable = () -> {
    if (currentProgress[0] < polyz.size()) {
        seekbar.setProgress(currentProgress[0], true);
        marker.setRotation(rotationList.get(currentProgress[0]));
        animateToCoodinate(polyz.get(currentProgress[0]), (int)(0.4 * playbackSpeed)); // ObjectAnimator
        polyLinePoints.add(target); polylineAnimated.setPoints(polyLinePoints);        // red visited trail
        currentProgress[0]++;
        playbackHandler.postDelayed(this, playbackSpeed);   // ← self-rescheduling, same pattern as JS
        if (endProgressForTimeline == progressValue) setPlaybackToReplay(this);
    } else setPlaybackToReplay(this);
};
🔁

Note the symmetry with the live map: Handler.postDelayed re-posting itself, not a fixed timer. playbackSpeed comes from the speed prop (speedTime = 1000ms, changeable via the 1×/2×/4× buttons). Position interpolation uses an ObjectAnimator with a custom TypeEvaluator over LatLng — this is why playback stays smooth for thousands of points where a JS implementation would drop frames.

Marker taps (onMarkerClick) cycle through stacked stop / over-speed / device-removed markers at the same coordinate via markerInfoStop / markerInfoOverSpeed / markerInfoDeviceRemoved hash maps.

§7API system

The model-based API system

Every screen instantiates a model with (context, pageName):

e.g. GpsActiveMap constructor 
truckModel      = new Truck(this, 'GpsActiveMap');
gpsModel        = new Gps(this, 'GpsActiveMap');
this.geofencingModel = new Geofencing(this, 'GpsActiveMap');
stopLocation    = new StopLocation(this, 'GpsTrackerTruckDetailsPage');

The model then:

  1. calls Functions.<transport>(endpoint, payload),
  2. on success writes the raw response onto the context (e.g. this.ctx.GpsAddress = responseJson) and calls a well-known callback on the context (e.g. this.ctx.fetchGpsAddressDone()),
  3. on failure calls this.checkErrorNetOrApi(error) which does a NetInfo.fetch() and opens either modalApiHitErrorVisibility or modalNoInternetVisibility,
  4. fires AnalyticFunctions.Analytics('Truck er Obosthan', <group>, 'try'|'success'|'fail', params) on every branch.
⚠

Consequence: a screen must implement the exact callback name the model expects, or the response is silently dropped.

§11Reference

Gotchas, dead code and footguns

Read this section twice. This is what separates "it compiled" from "it works."

01

Dead code in GpsActiveMap — animate(newCoordinate), renderCurrentLocationView() and onPressCurrentLocation() are never called. checkDistanceAndAnimate in the base class is only reachable through animate(), so it is dead too. Left over from the pre-AnimatedMarker bridge.

02

GpsTrackerBaseComponent.js is not the base class. The real one is views/GpsBaseComponent/index.js.

03

resetValueOnDropdown() mutates this.state directly and assigns to an undeclared allLocation (implicit global). Do not copy this pattern.

04

The loading modal is gated by three independent flags. Any new API added to the marker-press / mount path must either set its flag or the loader hangs. See getFetchFlag() in §4.

05

truckObject is mutated, not setState-d. The header only repaints because setState({region, markerRotation}) happens in the same function. If you add a field to truckObject and no setState follows, the UI will not update.

06

truckStatus is stale on the live map. The loop refreshes engineStatus but never recomputes truckStatus, so the active/inactive badge can disagree with the ignition icon until the screen is reopened or the truck is re-picked from the dropdown.

07

Native map guards. Every mapViewRef call is wrapped in if (this.mapViewRef && this.mapIsReady). Removing these guards reintroduces the native crashes noted in componentWillUnmount.

08

AnimatedMarker.polylineCoordinates grows unbounded for the life of the screen — one entry per animation frame. It is only cleared by stopAnimatingMarkerAlongPolyline() (unmount / truck switch).

09

MapView key={this.truckObject.imei_id} forces a full native map remount when the truck changes. That is why mapIsReady / mapViewRef are reset to false / null in selectDropDown.

10

GpsDemo/ and GpsTrackerDemo/ are near-duplicate trees used for the demo walkthrough (isGpsDemo = true). Changes to the real screens are not automatically reflected there.
